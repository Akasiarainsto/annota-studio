# Annota 标序 · 本地演示操作指南

此版本用于音频、视频、图片标注及面试操作演示。全部预置任务均为模拟场景；平台未连接真实模型、账号或多人后端。用户已确认发布至 GitHub Pages，在线入口为 <https://akasiarainsto.github.io/annota-studio/>。

## 一、启动与打开

最方便的方式：解压完整文件夹，双击根目录的 **`打开演示.html`**。它已内联本地脚本和样式，不需要安装依赖或联网；请保留旁边的 `assets` 文件夹。普通 `index.html` 是用于 HTTP / GitHub Pages 的模块化源入口。

如需 HTTP 预览，请使用随包支持媒体 Range 请求的服务，以保证音视频跳转和关键帧操作正确。不要用不支持 Range 的简单服务器替代。

在 PowerShell 中运行以下示例命令，命令中的端口为 8768：

```powershell
# 在解压后的项目根目录打开 PowerShell
python -X utf8 tests/preview_server.py 8768
```

保持终端运行，再打开 <http://127.0.0.1:8768/>。若 8768 已被使用，可将命令和浏览器地址一起换成其他未使用端口。已安装 Python 的其他机器也可运行 `python tests/preview_server.py 8768`。服务器只负责提供本地静态文件；没有数据上传服务。GitHub Pages 使用 `index.html` 即可，无需这个本地验证服务器。

## 二、先看懂页面

- 顶部切换“数据标注 / 数据质检 / 模型评测”。
- 左侧切换音频、视频、图片，并通过搜索和状态筛选选择任务。
- 中央用于观察或试听素材、查看时间轴及标注结果。
- 右侧只编辑当前选中的片段或对象，减少长表单同时展开。
- “帮助”中查看规则和快捷键；“恢复”用于导入此前的完整备份。
- “空白标注练习”创建可自行填写的练习，不把参考描述自动当成自己的标注。
- 左侧“JSON校验”和数据质检页的同名按钮打开独立文件校验器。

三个环节的通俗区分：

1. 数据标注：我在制作数据，记录素材里有什么。
2. 数据质检：我在检查数据，检查人工标注是否准确、完整、符合规范。
3. 模型评测：我在检验模型，把模型原始输出和要求或独立参考答案对照。

### 独立 JSON / JSONL 校验

1. 点击左侧“JSON校验”。默认跟随当前模态，载入其训练格式；顶部可切换 **Dolphin 音频 / Seedance 视频 / Seedream 图片**。三者字段、规则和样例各自独立。
2. 音频检查逐段转写、说话人、时间边界、方言枚举和噪声属性；视频检查固定七项 `captions`、时间与重叠原因；图片检查 Caption、标签、划分、路径和所选文件清单。具体契约见《分模态JSON校验与即时拦截》。
3. 先点“正常样例”，再点“全部异常”。音频是 5 条 / 5 个问题，视频是 3 条 / 3 个问题，图片是 13 条 / 17 个问题。下拉框可逐项演示越界、颠倒、缺转写、缺说话人、七项数量、标签重复或图片不存在等案例。
4. 点击问题定位原文中的字段；手动修改后，旧报告立即失效，点击“运行校验”复检。音频/视频有整批“修正后示例”，图片有“Caption 缺失 → 修正后”的成对练习；图片全部异常案例需要逐项修正。
5. 可导入本模态的 JSON 对象、对象数组或 JSONL。JSONL 每个非空行是一条记录；坏行报错后继续检查下一行。导入其他模态会明确提示类型不匹配。也兼容 Annota 当前标注与工作区备份，后者只检查所选模态并显示跳过数量。
6. 图片默认核对实际加载成功的随包图片。检查自有数据时，点击“选择图片根目录”，例如 JSON 引用 `images/a.png`，应选包含 `images` 子目录的父目录；随包可选 `examples/image` 练习。更换清单后须重新校验；“使用随包清单”可还原。音视频不读取外部文件时长，时间规则依据 JSON 声明的 `duration`。
7. 三个页签分别保留本次打开期间的编辑文本和格式。“载入当前标注”只在当前任务与所选模态一致时可用；转换过程不改原任务。关闭窗口会结束这次独立编辑。
8. 下载当前文本、问题 CSV 或最新报告 JSON。修改文本后，须复检才能下载最新报告。校验器不自动修正数据，不将文本写回任务库；迁移工作区另走备份恢复入口。

所有文件按提交/交付标准检查，未完成草稿也会提示缺项。图片清单核对不代表图片内容正确；结构、路径、枚举和时间通过也不代表转写、描述、审美或合规通过。校验与模型评测保持分开。

## 三、音频标注

1. 选择 Dolphin 音频任务，先试听。
2. 在波形中拖选区间，或填写起止秒数，创建片段。
3. 选中一个片段，在右侧填写转写、说话人、语言、方言、场景和混说等属性。非语音片段使用 Noise 等相应标签。
4. 通过片段试听、循环和倍速反复核对，确认片段边界与文本。
5. 检查器底部实时显示规则状态。方言使用枚举选择；纯噪声任务需要噪声/静音标签，转写可填约定标记，说话人可填“不适用”。
6. 未完成时仍可保存草稿。点击“提交质检”会复查；错误会阻止提交，点击问题定位字段，修正后再次提交。

预置语音是合成普通话，不能用它证明真实方言或维吾尔语识别效果。波形反映音频采样幅度；本地演示没有自动识别模型。

## 四、视频标注

1. 选择 Seedance 任务，播放并定位到要描述的内容。
2. 创建时间片段并设定起止点，描述该片段的动作或事件。
3. 填写当前片段的主体、动作时序、运镜、光影、物理动态、材质、交互七项 Dense Caption。
4. 如需演示目标轨迹，先选择目标框工具，在不同时间位置建立或调整关键帧。中间位置由线性插值显示；这是几何插值，不是 AI 跟踪。
5. 片段重叠时，在后续重叠片段填写重叠原因；首尾相接无需原因。保存，再提交质检。

1/30 秒前进或后退用于演示时间步进，不是对实际视频帧率的保证。片段不得越过真实媒体时长，关键帧轨迹只在其首末范围内出现。

预置小球片段为程序动画；异常片段是人为构造的教学错例。

## 五、图片标注

1. 选择 Seedream 任务，查看全图，必要时缩放。
2. 写整图 Caption，描述真实可见的主体、动作/状态、场景与光影，并选择内容标签。
3. 用矩形工具拖出目标框，选中对象后可调整标签和坐标，或删除、撤销。
4. 框坐标以图像范围内的归一化值保存；不要把空白背景或工具栏包含进目标框。
5. 保存草稿，完成后提交质检。

工作空间照片中的笔记本屏幕为黑色；请以实际画面为准。果铺图的数量和招牌文字由人工观察，不提供自动计数或 OCR。

## 六、导入自己的媒体

使用顶部“导入素材”，可选择音频、视频或图片文件。多文件会分别形成任务，切换到相应媒体类型查看。

- 结构化任务、标注与本地审核记录保存在当前站点的 localStorage。
- 导入的媒体文件存入当前站点的 IndexedDB；同一地址、同一浏览器刷新后可回读。
- 地址包含协议、主机和端口。换端口、换浏览器或隐私窗口可能看到不同的本地工作区。
- 清除站点数据会删除本地标注和媒体。重要结果请导出，同时自行保存源媒体。
- 若浏览器阻止存储、空间不足、文件编解码不受支持或媒体缺失，按界面提示处理；不能只看文件名就认定媒体已成功加载。

导入不上传素材到外部服务器。不要将真实客户数据放入待公开仓库或演示样例。

## 七、保存、质检与返修

状态流程为：草稿 → 待质检 → 已验收；发现问题则由待质检 → 已退回 → 修改重提。

1. 在标注页保存草稿，保留未完成工作。
2. 编辑时检查器底部即时显示规则结果；展开问题可定位字段。提交质检时再次执行对应模态的规则，错误任务保持草稿或退回状态，不能进入待质检。
3. 切到“数据质检”，人工核对内容，选择通过，或填写明确原因后退回。只有待质检且规则通过的任务才能验收；切换页面本身不等于状态流转。
4. 退回任务返回标注环节修订，再次提交。
5. 修改已提交或已审核的标注会使此前审核失效，需要重新提交和复核。

本演示由同一人在同一浏览器中切换环节，体现操作流程；没有真实双人隔离、身份认证或组织权限。结构检查通过只表示满足被检查的结构规则，不能自动证明转写准确、描述真实或内容合规。

## 八、模型评测单独演示

音频比较人为构造的 ASR 原稿与参考稿，演示 CER；不要把人工改对后的稿子当成模型输出。图像和视频使用明确标为模拟的对比素材，可按规则记录评分与比较结论。

评测结果不混入当前人工标注 JSON。没有可靠参考稿或模型原始输出时，不应把空缺替换成虚构的模型成绩。

## 九、导出与恢复

顶部“导出”用于下载当前标注或完整工作区备份：

- 当前标注 JSON：用于展示素材属性、片段、对象、Caption 与标签等标注结果，不含模型评测数据。
- 完整 JSON 备份：用于保留工作区任务状态和已有记录。
- 两类 JSON 都不包含媒体文件本体。迁移电脑时还须复制源媒体；恢复后若找不到导入媒体，需重新关联相应文件。

通过左侧“恢复”选择完整备份。恢复前检查结构和内容，不直接覆盖已有任务。若要把当前单任务标注作为正式生产格式，还需按目标数据规范另行转换、抽检与验收。

## 十、建议的五分钟面试演示顺序

1. 先说明：这是根据工作经历中的任务类型制作的本地模拟作品，样例不是客户数据。
2. 选音频，划一段、试听、写转写，再保存。
3. 切视频，展示时间片段和七项描述；切图片，现场画一个目标框。
4. 提交一个任务，进入质检，填写原因退回，再修改重提并验收。
5. 打开 JSON 校验，分别切三种模态，选专项错例、定位、修改并复检；再在标注页清空一个必填项，展示即时提示、保存草稿和提交拦截。
6. 有需要再进入模型评测，说明它检查的是模型输出，与标注制作分开。

## 十一、在线版本

当前源文件使用相对路径，适合后续作为静态站发布。GitHub Pages 只提供网站托管，不会自动成为多人标注后端，也不会同步各浏览器的本地数据。

用户于 2026-10-29 确认本版并要求发布，仓库为 <https://github.com/Akasiarainsto/annota-studio>。后续更新由 `main` 分支发布。发布过程与验证范围见《GitHub_Pages发布说明》。

本地文件与网站的浏览器存储相互独立，旧草稿不会自动出现在网站上。迁移前在本地导出完整备份，再到网站恢复；用户导入的媒体需自行保留并重新关联。发布静态网页不会上传本地工作区里的草稿和媒体。
