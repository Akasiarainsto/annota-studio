# Annota 多模态工作台 · 本地验收版

版本：3.0.0-local.3。按 2026-11-01 确认的设计重建，独立于旧版 annotation_studio。本轮没有发布、推送或修改 GitHub 旧站。

## 打开方式

Windows 双击根目录的 **启动本地演示.cmd**。启动器优先使用本机 Node.js，找不到时使用当前电脑已有的 Codex Node 运行时；要求 Node.js 24+。前端和服务端没有需要联网安装的 npm 依赖。

默认地址是 http://127.0.0.1:8788/ 。端口被其他工程占用时自动尝试 8789–8798；实际地址写入 `.local_data/local-url.txt`。启动器核对工程身份，不会停止或替换占用端口的其他服务。

不要双击 public/index.html，ES 模块、登录、保存和复核需要本地 HTTP 服务。停止服务可运行 **停止本地服务.cmd**；关闭页面或服务不会删除数据。若电脑重启，重新运行启动器即可继续。

## 演示账号

四个账号密码均为 `demo1234`，仅用于本地验收。

- `annotator`：标注员，处理音频、视频和图片任务。
- `reviewer_a`：复核员甲，独立提交本轮意见。
- `reviewer_b`：复核员乙，独立提交本轮意见。
- `manager`：项目负责人和独立仲裁员，查看项目统计、生成分层抽检方案、处理分歧。

同一浏览器可点击右上角“退出”依次登录；要同时演示两个账号，可用 Edge/Chrome 的不同浏览器配置或隐私窗口。账号身份、编辑权、复核权和仲裁权由服务端检查，不是前端切换显示名称。

## 复核意见提交后如何更正

如果另一位复核员尚未提交，在当前任务右下角点 **撤回复核并修改**，填写原因。原意见保留并标为已撤回，当前有效票数归零，然后可以重新填写独立复核；撤回记录不计入双人结果与 Kappa。

如果本轮双人结果已经形成，在右下角点 **申请更正复核结论**。填写误判位置与原因后，任务进入“复核更正待处理”，暂停作为已验收结果使用。用 manager 登录，进入质检找到任务，点 **处理复核更正**，选择重新发起双人复核或驳回申请，并填写依据。

负责人同意后，同一份冻结标注进入新一轮，两位复核员重新判断。原意见、更正申请、处理依据和旧轮次全部保留；被新轮次替代的配对不重复计入当前有效 Kappa。原标注不自动修改。若退回后标注员已经开始修订，则按修订重提流程继续，不能用旧冻结内容覆盖新稿。

## 撤销与拖选范围（local.3）

视频播放器下方现有明确的 **撤销 / 重做** 按钮，可恢复合并、分割、时间范围、Caption 和属性等最近编辑。Ctrl+Z / Ctrl+Shift+Z 也可使用；焦点在文字输入框时优先撤销文字，请点击工作区空白处后使用全局快捷键。撤销历史仅保留在当前打开的任务编辑会话中，刷新页面或离开后不会保留；保存草稿并不等于保存撤销历史。

音频和视频的 **拖选范围** 只产生临时选区，不立即改变标注。点击按钮后在时间轴按住拖动，松开后显示起止时间和四个操作：

- **新建片段**：只在没有已有片段的空白范围创建；重叠时提示具体冲突的片段编号。
- **调整当前片段**：先选中要修改的片段，再将其时间改为选区；不能覆盖其他片段，边界改后须重新人工确认。
- **导出选区**：允许覆盖已有标注，仅导出选定范围的真实 WAV / WebM，不修改片段与正文。
- **取消选区**：移除临时选区，保留原标注。

如果时间轴已被 0–8 秒片段全部覆盖，重新划分应使用播放点处的“分割”，或调整当前片段后再在空白处新建；不能用“新建片段”叠加覆盖原标注。合并后不合适则直接撤销，无须删除重做。

## JSON 错例与结果（local.3）

选择音频、视频或图片后，在下拉框选择错例，立即载入对应的实际错误 JSON 并执行校验；左上标明模态、任务与错例名称。“重新载入错例”用于恢复被修改过的错误样本。合格/错误样例使用固定教学任务，“当前任务”另行读取你的草稿。

手动修改正文后，右侧立即改为“待重新校验”，避免沿用上次的通过结果；点击“执行校验”读取当前全部文本。选着错例但已经修好 JSON 时应当通过，不能按错例名称强行报错。导出报告也会重新计算当前内容。校验只检查结构、字段与媒体约束，不代替人工内容判断。

## 建议的验收路径

1. 标注员打开“宁夏畜牧业”：播放、循环、拖边界、改时间、分割合并、撤销重做。将“胎羊皮”“皮章”修订为“滩羊皮”“皮张”，逐段确认，保存并提交。
2. 将 S03 结束时间临时改成 13.5，确认会提示越界、点击定位并阻止提交；草稿仍能保存。修正后再继续。
3. 从左侧 JSON 入口选择音频、视频、图片，分别载入合格样例和不同错例；编辑、校验、错误行列定位、JSONL、导入与导出报告。结构校验不判断内容是否真实。
4. 退出，分别登录甲、乙进入质检。先提交一份，确认任务没有直接通过且对方意见不可见；再提交第二份。双合格通过、双不合格退回、一致性分歧进入仲裁。
5. 用 manager 仲裁退回。标注员修订重提，确认原轮冻结结果和两份意见仍在，第二轮需要重新复核。
6. 视频任务操作时间轴、Caption 与七维按钮；图片任务画框、移动、四角缩放、修改类别、标记遮挡、缩放和平移。两种任务同样能提交真实复核。
7. 评测页左右同步播放、暂停、跳转、倍速，确认共同 8 秒处两边一起停；切“各自全片检查”看较长视频尾部，切换单侧音轨。填写低分理由并保存评测。
8. 顶部显式开始/暂停计时；切后台暂停。管理页查看来自实际任务的人效、进度、返工与 Kappa，再生成带种子和修订引用的分层抽检。

完整验收细项见 `docs/ACCEPTANCE.md`；运行结果见 `evidence/browser_report.json`。

## 已实现范围

音频：真实 PCM 波形、人工句段对齐、句段循环、倍速、边界拖动/输入、说话人和属性、分割合并、撤销重做、片段与结果导出。文字点击定位到句段，不宣传字词级对齐；新导入音频不会自动识别。

视频：实际原片、镜头片段、七维属性、Caption、边界确认、撤销重做、临时选区和片段导出；模型评测与标注分开。两个公开真实 A/B 案例保留原来源，固定教学编号不冒充随机盲评。原片时长不同，默认同步公共区间，尾部单独检查。

图片：实拍 Caption、场景/光线/标签、矩形创建、移动、四角调整、坐标输入、区域分类与遮挡、撤销重做、缩放和平移。坐标按原图像素保存。多边形、关键点与 3D 未纳入确认首版。

JSON：共用语法定位器、分模态业务规则，前后端复用纯验证模块。支持单对象、数组、JSONL、重复键、数值溢出、唯一 ID 和媒体约束；未通过人工确认不能提交。各模态有不同的合格/错误样例。

质检：独立真实账号、冻结轮次、双方意见封存、自动退回、独立仲裁、历史结果导出和重提；Kappa 只比较每任务最近完整一轮的配对，展示矩阵及不可计算原因。分层抽检保留总体、种子、比例、分层规则、任务版本和轮次。

存储：SQLite 服务端保存；浏览器保留未保存草稿用于恢复，冲突时不自动覆盖新版本；真实媒体复制到本机上传目录，刷新后可继续使用。

## 切片文件

“快捷切片”从当前播放点导出所选 3–10 秒 clip，并把范围记录在结果 JSON 的 `clips` 字段；它与人工语义句段分开，允许覆盖已有句段范围。尾部不足指定长度会要求调整播放点或长度。

音频导出真实 PCM16 WAV；内置样例保持 16 kHz。视频使用浏览器 Canvas + MediaRecorder 实时编码为 WebM（VP8/Opus），导出耗时约等于片段播放时长，切后台会取消。不是 MP4 无损切流，也不承诺帧级精确；本机测试请求 3 秒，实际 WebM 约 3.04 秒，含视频和原音轨。手工语义镜头可能短于 3 秒，不被快捷 clip 规则强行合并。

## 本地与后续部署边界

本版只监听 127.0.0.1，供这台电脑验收；账号和权限是真的，但尚未接入异地协作的云端服务。原需求中的账号、多人流程和服务端持久化在本地可验证，跨设备部署留待本地验收通过后处理。自动 ASR、复杂企业组织、计薪和模型生成 API 不在本轮。

导入视频时浏览器无法可靠读取 FPS，因此须由使用者填写实际帧率；内置案例的 24 fps 已解码核验。未知字段不伪装成自动测量结果。

## 工程与验证

`public/src/core` 是无外部依赖的纯业务规则；`services` 负责 HTTP、媒体 I/O 与导出；`editors` 和 `views` 分别处理交互与视图。`server` 以 SQLite 适配器隔离存储，任务服务集中检查权限、修订和状态。媒体读取统一使用 HTTP Range，避免本机浏览器环境中普通完整媒体请求被返回空内容。

运行 `node --test tests/*.test.js` 检查业务与 HTTP 流程。浏览器测试为 `node tests/browser-workflows.mjs`，依赖开发机已有的 Playwright 与 Edge，使用隔离的临时数据库；测试生成的操作不会写入用户演示数据库。外部测试工具路径可由 `PLAYWRIGHT_PATH`、`BROWSER_PATH` 覆盖。

运行时数据在 `.local_data`；交付压缩包不包含它，首次启动会建立新的演示数据。备份自己的作业请先停止服务，再复制该整个目录，或从工作台导出 JSON；不要以直接复制正在写入的单个 SQLite 文件代替完整备份。

素材来源、原始许可与第三方组件说明见 `docs/SOURCES.md` 和 `docs/THIRD_PARTY.md`。公开数据只是工作方法模拟，不代表用户亲自完成过这些公开数据或模型项目。
