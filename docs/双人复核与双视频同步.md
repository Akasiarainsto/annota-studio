# 双人复核与双视频同步

更新日期：2026-10-29。对应用户确认的两项恢复要求，发布目标沿用 <https://akasiarainsto.github.io/annota-studio/>。

## 原项目对照与根因

原项目 `seed_workbenches/shared/app.js` 的 `reviewRecord`、`playPair` 与《数据契约》规定：首轮独立意见后由不同姓名第二次确认；分歧可仲裁；重新提交创建新周期。视频对比提供“从 0 秒联合播放”。Dolphin 的独立工作台也保留复核周期与不同姓名的确认机制。

当前版本曾将复核简化为一次“通过验收”，没有复核人和周期；A/B 页面只渲染各自原生播放控件，没有统一控制器。本次从状态机与播放器生命周期两个源头恢复，保留现有纯前端架构和本地数据。

## 双人复核

1. 标注通过结构检查后，点击提交，进入 `pending`，`reviewRound` 加一。
2. 第一位填写姓名、独立意见并勾选三项核对项，点击“记录首轮通过意见”。记录 `opinion`，任务仍为待质检，显示 1/2。
3. 另一姓名填写自己的意见并核对，点击“第二人确认验收”，记录 `approved` 后进入已验收。同一姓名不允许重复确认，比较时去首尾空白、统一全半角与英文大小写。
4. 姓名和意见对所有决定均必填。任一位可带理由退回；有分歧可进入 `disputed`，由填写仲裁结论的人通过或退回。仲裁通过记录 `arbitrated`，不会假装是普通第二人通过。
5. 不允许重复提交待质检、已验收或待仲裁任务来重置流程。修改后回到草稿，重提开启新周期，旧意见保留但不能充当本轮意见。撤销标注也不会删除已发生的复核历史。
6. 通过意见要求结构规则通过、实际媒体已载入并完成三项人工核对。退回和分歧不以“通过检查”为前提。

音频、视频和图片共用上述规则。记录字段包括 `id / round / revision / reviewer / note / decision / at`，任务使用可选 `reviewRound`；工作区备份仍为 `annota/1`。备份恢复检查新周期的姓名、决定、修订引用和状态顺序，拒绝将首位缺失或同名的意见伪装为双人验收。

旧数据没有 `reviewRound` 时按旧契约读取，保持任务、状态、意见和媒体。旧版已验收记录显示“旧版验收”，不生成不存在的第二位意见；修改后重提使用新流程。旧版待质检任务启动一个新格式周期，旧记录不会被计入该周期的双人证据。

实现分工：`review-workflow.js` 是纯状态机与审计检查，`review-view.js` 渲染表单与历史；`app.js` 协调媒体检查和保存，`core.js` 在备份验证中调用状态检查。没有账号、真实身份验证或跨用户意见隔离，这与原项目的本地演示边界一致。

## 左右视频同步

进入视频“小球运动”任务的“模型评测”，A/B 两侧下方提供：

- 同步播放与同步暂停，空格键也控制两侧。
- 从头同步播放：两侧回到 0 秒并共同开始。
- 统一进度条：按绝对秒数跳转两侧，播放中跳转可继续，拖到末尾则一起停止。
- 统一倍速：0.5、0.75、1、1.25、1.5、2 倍。
- 自动漂移校正：左侧作为时间参考，时间差超过 80 毫秒且非跳转状态时调整右侧。浏览器仍可能存在解码与渲染偏差，不作为专业逐帧测量。
- 以两侧较短的有效时长为共同范围，结束时一起停止；任一侧缓冲时一起等待，双方可播放时恢复；任一侧加载/播放失败时一起暂停并提示。
- 切换任务、模态或环节时暂停旧播放器，注销事件和动画循环，避免后台继续播放。

`video-comparison.js` 独立管理同步控制。评测播放不修改标注修订、复核状态或模型评分，不影响独立 ASR 原稿与 CER。

## 验证

本地测试必须通过后才推送发布，再在正式网址运行同一浏览器专项测试。

- `node --test tests/core.test.mjs tests/json-validation.test.mjs tests/review-workflow.test.mjs`：59 项规则测试，含 10 项双人状态机检查。
- `tests/review-sync-browser.cjs`：8 组专项交互，覆盖不同姓名、姓名变体拦截、意见必填、刷新回读、修改/撤销后历史保留、新周期、退回/仲裁、三模态共用、旧数据保留、双视频联合控制、漂移、缓冲、较短时间范围、错误与离页停止、小屏布局。
- `tests/browser-workflow.cjs`：14 组媒体及原有流程回归，审核用例已改为真实的两次姓名意见。
- `tests/json-validator-browser.cjs`：12 组分模态 JSON 校验与提交拦截回归。

时长不等的专项测试在右侧 video 元素载入随包 1.5 秒 WAV，使用真实媒体时钟检查公共时间范围与结束；正常同步测试使用两段真实 WebM 动画。缓冲测试通过媒体事件模拟等待，同时检查两侧真实播放状态。测试结果不代表在所有网络、编解码器与设备上达到逐帧同步。

结果文件：`review_sync_verification.json` 为本地专项；正式网站测试写入 `pages_review_sync_verification.json`，原有报告继续分别保存。设置 `ANNOTA_BASE_URL` 可指定正式网址；不设置时使用支持 Range 的本地预览服务。浏览器测试使用独立上下文，不修改用户当前浏览器的草稿。
