# 分模态 JSON 校验与即时拦截

更新日期：2026-10-29。所有案例是教学构造，不是客户数据。对应演示入口是根目录 `打开演示.html`，左侧“JSON校验”。

## 为什么重写

旧版三个模态共用 Annota 任务格式与混合错例，未表现各自的训练格式。本版参考“面试知识问答查询补充”对话对应项目的 `seed_workbenches/shared/json-validation.js`，以及 `JSON校验演示.md`、`视频JSON校验演示.md`、`DolphinJSON校验演示.md`，拆成音频、视频、图片三个纯规则模块。共用解析、定位、批次检查，界面选择对应模块。既有媒体、草稿与审核存储格式继续使用 `annota/1`。

## 音频：Dolphin

必填字段为 `id / source_id / audio_file / duration / language / dialect / scene / kind / segments / noise_tags`。每个片段要求 `start / end / text / speaker`；可选 `asr`、顶层 `reference` 必须为字符串，可以为空。兼容旧版 `{project:"dolphin", schema_version:1, records:[...]}` 包装。

- 时长必须是大于零的有限数；时间单位为秒，满足 `0 ≤ start < end ≤ duration`。
- 当前单通道规则不允许片段重叠，首尾相接允许；混说需要人工复核。
- 转写与说话人不能为空；非语音也需用约定标记说明，说话人可填“不适用”。
- `kind` 仅为 `speech / noise`；`dialect` 使用界面所列枚举；`noise_tags` 使用约定噪声标签，纯噪声任务至少一项。
- ID 同批唯一；音频路径必须是根目录内的文件名或相对路径，并符合扩展名约定。未检测实际音频文件与解码能力。

10 个案例：正常、超时、起止颠倒、缺转写、缺说话人、缺噪声标签、全部异常、修正后、单通道重叠、方言枚举错误。全部异常为 **5 条 / 5 条不通过 / 5 个问题**；修正后保持对应编号，5 条全部通过。

## 视频：Seedance

必填字段为 `sample_id / video_path / duration / segments / split`。片段为 `start / end / captions`，发生重叠时还需 `overlap_reason`。

- `captions` 是固定七项数组，顺序为主体身份与外观、动作序列与时序、运镜变化、光影氛围、物理动态、材质与纹理、场景交互。每项都必须为非空字符串；不可观察时应写明原因。
- 时间满足 `0 ≤ start < end ≤ duration`。与音频不同，视频允许重叠，但后续重叠片段必须说明原因；相接不算重叠。
- ID 同批唯一；相对路径合法、扩展名符合约定；`split` 为 `train / validation / test`，同一规范化视频路径不可跨划分。

8 个案例：正常、超时、起止颠倒、缺动作描述、全部异常、修正后、重叠缺原因、七项数量错误。全部异常为 **3 条 / 3 条不通过 / 3 个问题**；修正后 3 条全部通过。

## 图片：Seedream

必填字段为 `sample_id / image_path / caption / tags / split`。本训练格式没有音视频时间字段。

- Caption 为非空字符串；文本字段类型与首尾空白分别检查。
- `tags` 是非空数组，标签只能使用约定集合，同一条内不可重复；`split` 为 `train / validation / test`。
- 规范化相对路径，禁止绝对路径、NUL 和越出根目录的路径，检查图片后缀；核对当前图片文件清单。
- ID 同批唯一；同一规范化图片路径不可跨数据划分。重复 ID 和跨划分冲突会标记所有涉及记录。
- 路径大小写按本地 Windows 教学规则统一。生产数据若使用大小写敏感对象存储，需要按实际规范调整，清单核对不能代替部署检查。

7 个案例：正常、Caption 缺失、Caption 修正后、全部异常、非法/重复标签、图片不存在、路径越界。全部异常为 **13 条 / 13 条不通过 / 17 个问题**，覆盖原版重复 ID、缺字段、类型、标签、路径、引用、划分、重复键与语法案例。“修正后示例”按钮对应 Caption 单条练习，全部异常需要逐项修正。

随包清单只加入浏览器实际加载成功的演示图片。自有数据可选择图片根目录：若引用 `images/a.png`，就选包含 `images` 的父目录。随包 `examples/image` 可用于目录选择练习。文件清单仅证明该相对路径有对应文件；不识别内容、质量、图文一致性、文件损坏或近重复。

## 解析、定位、编辑与报告接口

纯函数入口为 `validateAnnotationText(text, format, {modality, inventory})`，`modality` 为 `audio / video / image`，`format` 为 `json / jsonl`，`inventory` 是规范化文件路径集合。报告包括规则版本、模态、记录数、通过/失败数、问题、跳过数量与检查范围。问题包括错误码、字段路径、记录序号、样本 ID、行列和原文偏移。

JSON 支持单条对象或对象数组；JSONL 每个非空行一条记录，语法坏行报错后继续，保留真实物理行号。解析器检测重复键、非有限数与输入限制。单次最多 200 万字符、1000 条记录。

`toTrainingRecord(task)` 将 Annota 工作台任务只读转换为本模态训练格式：视频命名描述转为固定七项数组；音频的共同属性使用首段属性，段内语言/方言/场景保留；音频来源标识从任务或媒体标识取得，不虚构来源。独立训练格式不包含目标框；原 Annota 文件仍额外检查坐标和关键帧结构。工作台导出与备份保持原格式。

原生异模态记录会报告 `MODALITY_MISMATCH`。Annota 工作区备份只检查当前模态，明确显示其他模态被跳过；模型评测文件不能充当标注数据。

编辑文本或更换图片清单会使旧报告失效；重新运行后才能下载最新问题 CSV / 报告 JSON。可单独下载编辑文本。三个页签分别保留本次窗口中的编辑状态，关闭窗口后结束独立编辑，不写回任务库。

## 即时校验与状态拦截

`validateLiveTask(task)` 复用同一模态规则并保留工作台坐标、关键帧及元数据检查。编辑字段后，检查器底部立即显示规则状态；有错误可展开，点击定位原字段。方言等固定值使用选择控件，噪声标签使用切换按钮。

1. 清空音频转写，立即提示缺项，仍可保存草稿。
2. 点击“提交质检”，显示拦截问题，任务仍为草稿，不能进入待质检。
3. 修正转写，状态变为规则通过，再次提交后进入待质检。
4. 视频将结束时间改为 0，提示起止颠倒；改回有效时段即可继续。相同规则还会检查越界、七项描述和重叠原因。
5. 验收要求任务已待质检且规则通过；可切到质检页查看错误，页面切换不等于完成状态流转。修改已提交/验收的标注会使旧审核失效。

这些行为实现了用户截图中的即时反馈、必填/枚举/时序硬性检查及不合格数据拦截。本演示没有实测生产工时，因此不把截图的“节省约 80%”作为本平台验证结果。

## 验证与边界

- `tests/core.test.mjs` 与 `tests/json-validation.test.mjs`：49 项规则测试通过，覆盖三套样例、重复与划分、图片清单、定位、适配、实时规则。
- `tests/json-validator-browser.cjs`：12 组交互验证，覆盖三模态案例、编辑复检、目录、导出、小屏、即时反馈、草稿及提交拦截。
- `tests/browser-workflow.cjs`：14 组原流程回归，覆盖媒体播放、时间与目标框、保存恢复、审核流转、独立 CER、离线和小屏。

报告位于 `docs/json_validator_verification.json` 与 `docs/browser_verification.json`。检查结果证明当前演示的规则与流程行为，不替代用户验收。音视频时间依据声明元数据；结构通过不能判断转写、语义、审美、合规或模型质量。没有模型推理、生产权限或多人服务。
