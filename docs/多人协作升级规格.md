# 多人协作升级规格

2026-10-30：用户确认升级为真实账号、服务端存储和跨设备协作，并要求下载实际音频/视频 clip 文件。现有公开演示在新版完成前继续运行。

## 架构与范围

前端保留 HTML/CSS/原生 JavaScript 与当前浅色工作台。GitHub Pages 承载前端；Neon 承载托管认证、Postgres、私有媒体存储和服务端 API。开发与生产使用独立数据库分支。云端账号通过认证令牌识别，姓名文本不再作为身份依据。

项目负责人创建项目，生成有期限、单次使用的加入码，成员登录后加入。支持负责人、管理者、标注员、复核员；邀请操作不自动发送邮件。项目之间隔离；人员、任务、工时、标注、媒体、质检意见与审计事件存服务端。修改使用版本检查，防止两台设备静默覆盖。

旧的匿名本地演示继续可用，旧草稿不自动上传；登录后由用户选择迁移或在项目中创建任务。云端只把授权媒体返回给项目成员。

## 片段和音文对齐

音频波形与视频时间轴增加 3–10 秒片段长度选择；从当前播放位置一键生成指定长度片段，媒体剩余长度不足时明确拦截，不把不足时长冒充完整片段。音频每段的起止时间、转写和试听联动，供人工音文对齐，不声称自动 ASR/强制对齐模型。

当前片段可导出实际 WAV 或 WebM 文件，另可导出片段标注 JSON。视频导出采用浏览器重编码，显示录制进度并支持取消；不能只截取原文件字节或用改扩展名代替剪辑。必须验证文件可解码、片段时长与内容来源，明确浏览器编码能力限制。

## 抽检、独立复核和自动处理

项目管理者按媒体模态、难度或标注员分层，配置抽样比例与随机种子。保存候选总体、分层数量、选中 ID 和任务修订，抽样可复现。已修改的样本标为过期，不沿用旧判断。

每个样本分配两个不同的真实复核账号，标注员不能自审。两人分别作出合格/不合格判断和意见；第二份提交前隐藏对方判断。服务端保存独立意见并检查权限；隐藏不依赖前端按钮。

双人一致合格则通过；一致不合格则自动退回并保存原因；判断分歧进入待仲裁，由有权限且未参与该样本标注的管理者处理。结构校验失败在提交时由服务端拒绝；已提交记录若校验不合格则留痕打回。未抽中的样本不因某个抽检失败而被当作已检查。

Kappa 只使用同一规则、同一修订、两名指定复核人已完成的二分类成对样本。显示样本数、混淆矩阵、观察一致率 Po、机会一致率 Pe 与 κ=(Po−Pe)/(1−Pe)。Pe=1、没有有效配对时显示不可计算；不把顺序点击“通过”视为独立分类，也不混入旧版复核或模拟履历数字。

## 项目看板与统计口径

看板按项目、人员、媒体类型显示任务状态与进度，支持分配负责人、难度和成员。指标均由服务端记录计算：

- 进度：已通过的去重任务数 / 当前分配任务数。
- 人效：已通过去重任务数 / 有效作业小时；没有有效工时显示暂无数据。不同媒体分开查看，不把图像条数和音频时长当成同一工作量。
- 返工率：曾被退回的去重任务数 / 曾提交的去重任务数，重提不清零历史退回。
- 工时：显式开始/暂停计时，服务端时间戳与心跳确定有效时长；离开页面暂停。不是根据打开页面时长推断全员工作量。

## 自动化校验

复用现有分模态 JSON/JSONL 规则与错误定位；云端提交再次执行相同规则，不能通过直接请求跳过。检查字段、类型、枚举、路径与时间边界，不替代转写、图文一致性、审美或合规的人工判断。

## 验收

至少三个独立账号/浏览器上下文走通创建项目、加入、分配、上传、编辑、冲突拦截、计时、提交、分层抽检、两人独立判断、Kappa、退回/仲裁、看板汇总。直接 API 请求验证匿名拒绝、跨项目隔离、自审拒绝、查看未完成对方判断拒绝、伪造他人身份拒绝。真实媒体导出要实际解码和核对时长。通过本地与云端验证后才切换正式前端。
